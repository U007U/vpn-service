## Смена цен тарифов на $0.99 / $1.99 / $4.99

Новые цены в minor units (доллары, как сейчас): **7 дней 149→99, 30 дней 499→199, 90 дней 1049→499**. Минимальный платёж Stripe (MIN_CHARGE_MINOR.usd = 50) соблюдён для всех трёх.

### 1. Источник истины — сид (`scripts/seed.ts`, строки 49/56/63)
Меняю `priceMinor` в массиве `PLANS`: `149 → 99`, `499 → 199`, `1049 → 499`. Это обновит БД при повторном запуске сида (скрипт сверяется по `name` и апдейтит in-place).

### 2. Рабочая БД (`data/app.db`)
⚠️ Важно: Playwright `webServer` = `build && preview` и **не запускает сид**. e2e-тесты читают существующую БД, поэтому сида недостаточно. После правки сида выполню `UPDATE plans SET price_minor = ... WHERE name = ...` напрямую по БД (better-sqlite3 / sqlite3 CLI) для трёх тарифов, чтобы рабочая БД и e2e-среда совпали с сидом.

### 3. E2E-тесты — обязательно сломаются, пересчитываю
Они хардкодят `PLAN_PRICE_MINOR = 499` (тариф `'30 дней'` из сида) и производные суммы скидок:
- **`e2e/stage3.e2e.ts`**: `PLAN_PRICE_MINOR 499 → 199`; комментарий на стр. 216 «Сервер оценил это в 499» → «199».
- **`e2e/stage6.e2e.ts`**: `PLAN_PRICE_MINOR 499 → 199` (стр. 30, и в `paidEvent` стр. 60).
- **`e2e/stage4.e2e.ts`** — самая хрупкая, считает производные скидки:
  - `PLAN_PRICE_MINOR 499 → 199`
  - `DISCOUNTED_MINOR` (START30 = −30%, `floor(199×0.30)=59`, итого `199−59=140`): **350 → 140**
  - ассерты в чеке: `'3,50'` (350) → `'1,40'` (140) (стр. 136)
  - админ-код 50% (`floor(199×0.50)=99`, `199−99=100`): `paidEvent(publicId, 250)` → `(publicId, 100)` (стр. 227) и комментарий «половина от 499» (стр. 222)
  - комментарий «499 minor units … должен быть 350» (стр. 9) → «199 minor units … 140»

### 4. Статичные HTML-макеты — меняем цены, убираем скидки (по решению пользователя)
**`vpn-miniapp.html`** (зеркалит сид):
- `TARIFFS`: `price: 149→99, 499→199, 1049→499`; для 90 дней `old: 1497 → old: null`, `badge: '−30%' → badge: null`
- `USER.history` (стр. 160-162) — демо-данные: привожу к тем же ценам (`price: 499→199, 149→99`), запись со скидкой START30 (349) — убираю скидку, ставлю согласованную цену. Рендер `old`/`badge` (стр. 239/246/252) автоматически прячется при `null`, трогать логику не нужно.

**`vpn-mockup.html`** (стр. 829/839/851) — дизайн-макет с ценами `$2/$5/$12`:
- меняю на `$0.99 / $1.99 / $4.99`
- убираю бейджи `−40%` (стр. 840) и `−55%` (стр. 852)

### Чего НЕ трогаю (и почему)
- **Все unit-тесты `*.spec.ts`** (`checkout.spec.ts`, `checkout-service.spec.ts`, `price-calculator.spec.ts`, `payment-webhook-service.spec.ts`, `plan-service/plan-write/input.spec.ts`, `subscription-provision.spec.ts`, `fixtures.ts`): они создают тариф в памяти с собственным `priceMinor: 499` и проверяют результат сами по себе — **не зависят от сида и остаются зелёными**. Менять их = подгонять тесты под цену, которой там нет (499 — это абстрактное тестовое число, не «цена 30-дневного тарифа»). Оставляю как есть.
- Тип валюты (`usd`), форматтер `formatMoney`, `money.ts` — без изменений.
